# Worklog
Сервис для цифрового учёта выполненных работ и оказанных услуг.

Статус: MVP (в разработке)

Тип проекта: pet-проект + прикладной инструмент для реального использования

## О проекте
На текущем месте работы учёт оказанных услуг ведётся вручную (таблица на бумаге):

| № | Дата | Работа | Стоимость | Клиент |

Отсюда ожидаемые проблемы:
- долгое заполнение
- ошибки при подсчётах
- неудобный поиск и анализ
- отсутствие централизованного хранения данных

Worklog решает эту задачу, переводя учёт в цифровую систему с API и будущим UI.

## Цели проекта
- Упростить учёт выполненных работ
- Снизить количество ошибок при расчётах
- Обеспечить быстрый доступ к истории услуг
- Подготовить основу для расширения (UI, авторизация, аналитика)

## Текущий функционал (MVP)
- REST API для управления сущностями
- Модель данных и бизнес-логика
- Работа с клиентами и услугами
- Учёт истории выполненных работ
- Репозиторный слой
- Запуск через Docker Compose

## Доменные сущности
- `Client` — клиенты
- `Offering` — услуги и базовые цены
- `AltPrices` — альтернативные цены для отдельных клиентов
- `History` — журнал оказанных услуг (основная сущность)

## Конфигурация (.env)

Все переменные задаются через `.env`:

(`.env.dev` - для разработки; `.env.prod` - для развёртывания)

**Приложение**
- `APP_HOST` - хост (для Docker: 0.0.0.0)
- `APP_PORT` - порт
- `ENVIRONMENT` -  dev / prod

**База данных**
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_HOST` (в Docker: db)
- `POSTGRES_PORT` (обычно 5432)
- `POSTGRES_DB`

**Безопасность** (пока заготовка)
- `SECRET_KEY`
- `ACCESS_TOKEN_EXPIRE_MINUTES`

## Быстрый запуск

### Требования:
- установленный Docker Docker

### Запуск:
2 режима:
- **product**: `docker compose --profile prod up --build -d`
- **development**: `docker compose --profile dev up --build --watch`
